# 밤의 작은 상담소 — 프로젝트 기초 지침

2026년 11월 20일 기준. 원본은 Claude의 지침 문서이고, 이 파일은 그 사본이다. 둘이 달라지면 원본을 먼저 고치고 이 파일을 맞춘다.

## 이 문서의 쓰임

밤의 작은 상담소는 정해진 시간에만 불이 켜지는 1:1 온라인 상담실이고, 상담사 한 명이 손님 한 명과 채팅과 타로 카드로 이야기한다. 이 문서는 그 상담소를 프로토타입에서 실제로 운영할 수 있는 완성본으로 만드는 프로젝트의 기준이다.

- Claude 프로젝트의 지침 칸에 이 문서를 그대로 넣거나 링크로 참조한다. Claude Code에서는 저장소의 `CLAUDE.md`가 이 문서를 요약해 가리킨다.
- 새로운 결정이 이 문서와 어긋나면 작업을 멈추고 문서를 먼저 고친다. 코드가 문서보다 앞서가지 않는다.
- 출발점은 이미 만든 프로토타입 「밤의 작은 상담소」다. 분위기의 뿌리는 「밤의 작은 성당」에 있다.
- 맨 아래 「결정 기록」의 남은 항목은 사용자만 정할 수 있다. Claude는 권장안을 내되 대신 정하지 않는다.

## 정체성과 원칙

상담소는 촛불 하나가 켜진 작은 방이고, 손님은 아무것도 증명하지 않아도 되는 자리에 앉는다. 기능을 더하거나 빼는 모든 결정은 아래 다섯 원칙으로 판단한다.

1. **조용함이 먼저다.** 한 번에 손님 한 명만 받는다. 알림, 배지, 점수, 광고처럼 주의를 끄는 요소는 넣지 않는다.
2. **남지 않는다.** 대화와 카드는 상담이 끝나는 순간 서버에서 지워진다. 손님에게 이 약속을 화면에서 분명히 말하고, 코드가 그 약속을 지킨다.
3. **열려 있을 때만 존재한다.** 상담사가 문을 열어야 불이 켜진다. 닫힌 시간에는 닫힌 문과 다음 열리는 시간만 보인다.
4. **카드는 정직하다.** 섞인 순서는 뒤집히기 전까지 손님 쪽에서 알 수 없고, 상담사도 손님이 고른 카드를 바꿀 수 없다.
5. **사람이 상담한다.** 상담사의 말은 모두 사람이 쓴다. AI가 상담사를 대신하거나 답을 자동으로 만들지 않는다.

두 원칙이 부딪치면 위에 있는 것이 이긴다.

## 범위

1차 완성본은 서로 다른 기기의 상담사와 손님이 실제로 연결되어 30분 상담 한 번을 처음부터 끝까지 마칠 수 있는 상태다.

| 영역 | 1차 완성본에 만드는 것 | 만들지 않는 것 |
| --- | --- | --- |
| 공간 | 2D로 그린 상담실 한 칸, 문과 촛불 연출 | 3D 공간, 아바타, 여러 방 |
| 대화 | 실시간 채팅, 입력 중 표시, 끊김 후 다시 이어지기 | 음성·영상 통화, 파일·사진 전송 |
| 타로 | 완성된 카드 그림, 섞기·고르기·뒤집기 동기화, 카드 크게 보기 | AI 자동 해석, 혼자 뽑는 무인 타로 |
| 영업 | 상담사의 문 열기·닫기, 닫힌 문 화면, 대기 화면, 상담 시간 타이머 | 동시에 여러 손님, 상담사 여러 명 |
| 입장 | 상담마다 발급하는 초대 링크, 이용 약속 동의 | 회원가입, 손님 프로필, 상담 이력 |
| 종료 | 대화와 카드 삭제, 지워지는 연출, 마침 인사 화면 | 대화 내보내기, 녹음, 서버 백업 |
| 예약·결제 | 사이트 밖에서 처리(폼, 메신저, 외부 결제 링크) | 사이트 안 예약 시스템, 결제 연동 |

「만들지 않는 것」은 1차 완성본이 실제 상담에 몇 번 쓰인 뒤에 다시 검토한다. 그 전에 요청이 들어오면 Claude는 이 표를 가리키고 확인을 받는다.

## 사용자 여정

상담소는 닫힘, 대기, 상담 중, 마침 네 가지 상태 중 하나에만 있고, 두 화면은 항상 같은 상태를 본다.

상태 전환:

- 닫힘 → 대기: 상담사가 문을 연다.
- 대기 → 상담 중: 손님이 자리에 앉는다.
- 상담 중 → 마침: 상담사가 마친다.
- 마침 → 대기: 대화와 카드를 지우고 다시 손님을 기다린다.
- 대기 → 닫힘: 상담사가 문을 닫는다.

상태를 바꾸는 것은 손님이 앉는 순간 하나를 빼면 모두 상담사다.

| 상태 | 손님 화면 | 상담사 화면 |
| --- | --- | --- |
| 닫힘 | 닫힌 문, 다음에 열리는 시간, 위기 안내 | 로그인, 「상담소 열기」 |
| 대기 | 불 켜진 문, 이용 약속, 「자리에 앉기」 | 초대 링크 만들기, 손님 기다리는 중, 「문 닫기」 |
| 상담 중 | 카드 자리와 대화창, 남은 시간 | 같은 방에 스프레드 선택, 섞기, 펼치기, 카드 키워드, 위기 안내 보내기, 「상담 마치기」 |
| 마침 | 대화가 지워지는 연출, 마침 인사 | 지워졌다는 확인, 다음 손님 대기로 돌아감 |

흐름이 어긋날 때의 규칙도 미리 정해 둔다.

- **연결이 끊기면** 상담은 그대로 남고, 양쪽 화면에 상대가 잠시 자리를 비웠다고 표시한다. 같은 기기로 돌아오면 이어진다. 새로고침처럼 3초 안에 돌아오는 끊김은 표시하지 않는다.
- **시간이 다 되면** 알려주기만 하고 자동으로 끊지 않는다. 마치는 것은 상담사다. 남은 시간은 상담사가 손님이 앉은 것을 처음 본 때부터 세고, 두 화면에 분 단위로 같게 보인다. 5분 전부터 촛불색으로 바뀐다.
- **상담 중에 다른 사람이 오면** 손님이 계신다는 안내만 보인다. 대기 순번은 만들지 않는다.
- **손님이 먼저 나가면** 상담사에게 알리고, 상담사가 마치기를 눌러 지운다. 손님 화면에는 「나가기」 단추가 있고 두 번 눌러야 나간다. 나간 손님은 같은 링크로 돌아올 수 없다.

## 화면과 디자인 원칙

프로토타입의 틀(위쪽 촛불, 가운데 카드 자리, 아래 부채꼴 덱, 옆의 대화창)은 그대로 두고 완성도를 올린다. 새 화면을 더할 때도 같은 방 안에 있는 것처럼 보여야 한다.

| 항목 | 규칙 |
| --- | --- |
| 색 | 밤 `#07080f` 바탕, 상아색 글씨 `#ece7db`, 흐린 글씨 `#aeabb8`, 촛불 `#f3b25a` 하나만 강조색. 카드 뒷면은 자주 `#36284e`, 앞면은 상아 `#efe8d8`. 밝은 테마는 만들지 않는다. |
| 글씨 | 제목과 상담사의 말은 나눔명조, 그 밖의 본문과 단추는 Noto Sans KR. 본문 16px, 가장 작은 글씨 13px. |
| 빛 | 빛은 촛불에서만 나온다. 열림·닫힘, 상담 시작·끝은 불이 켜지고 꺼지는 것으로 표현한다. |
| 움직임 | 느리고 적게. 카드 섞기, 뒤집기, 대화가 지워지는 연출 세 가지에 공을 들인다. `prefers-reduced-motion`에서는 모두 끈다. |
| 소리 | 기본은 무음. 손님이 앉을 때 상담사 쪽에만 작은 종소리 한 번. 손님 쪽 소리는 켜기를 누른 경우에만. |
| 문구 | 상담사는 화면과 대화에서 present라는 이름으로 표시한다. 해요체, 짧은 문장, 느낌표와 이모지 없음. 안내 화면만 예외로 합니다체를 쓰고, 정보 목록과 present 소개는 명사로 끝낸다(상담실 안과 이용 약속은 손님에게 건네는 말이라 해요체 그대로다). 오류도 같은 목소리로 말한다(“연결이 잠시 끊겼어요. 다시 잇는 중이에요.”). |
| 화면 크기 | 손님은 휴대폰이 기준이다. 폭 360px에서 카드 자리가 위, 대화가 아래로 쌓이고 입력창이 키보드에 가려지지 않는다. 상담사는 PC 기준이다. |
| 접근성 | 누를 수 있는 것은 44px 이상, 키보드 초점이 보이고, 카드와 새 메시지는 화면 낭독기가 읽을 수 있다. |

성당에서 가져오는 것은 밤의 색, 글씨, 촛불, “적은 말은 남지 않는다”는 태도다. 성당의 말투(반말)와 종교적 상징, 3D 공간은 가져오지 않는다.

## 타로 규칙

카드는 상담사가 섞고, 손님이 고르고, 상담사가 펼친다. 이 순서와 권한은 화면뿐 아니라 데이터 규칙으로도 강제한다.

- **덱.** 목표는 메이저와 마이너를 합친 78장 전체다. 카드 목록은 코드 한 곳에만 두고 처음부터 78장 구조로 만든다. 그림이 늦어지면 메이저 22장으로 먼저 공개하고 마이너 56장은 공개 뒤에 채운다. 78장을 펼쳤을 때 휴대폰에서도 한 장씩 고를 수 있는지 2단계에서 확인한다.
- **그림.** present가 쓰는 유니버셜 웨이트 덱으로 익힌 리딩이 그대로 통해야 한다. 카드마다 웨이트 계열의 인물, 자세, 핵심 상징, 구도를 따르고, 번호와 이름 체계도 그 덱과 맞춘다. 그림은 1909년 원본 도상을 기준으로 상담소의 색과 선으로 새로 그리며, 유니버셜 웨이트 판의 채색이나 스캔 이미지는 쓰지 않는다. 그리기 전에 카드별 필수 상징 목록을 만들어 present의 확인을 받고, 공개 전에 그림 사용 권리를 한 번 더 확인한다.
- **스프레드.** 한 장(지금 마음)과 세 장(지나온 것, 지금, 다가올 것) 두 가지. 상담사가 고른다.
- **섞기.** 상담사 브라우저에서 `crypto.getRandomValues`로 순서와 정·역방향을 정한다. 섞인 순서는 상담사만 읽을 수 있는 곳에 저장한다.
- **고르기.** 손님은 뒷면만 보이는 카드의 위치를 고른다. 손님 브라우저는 그 위치에 어떤 카드가 있는지 받지 않는다. 한 번 고른 자리는 바꾸지 못한다.
- **펼치기.** 상담사가 한 장씩 펼친다. 펼치는 순간 그 카드의 이름과 방향이 양쪽 화면과 대화에 나타난다. 펼친 카드를 누르면 크게 볼 수 있다.
- **해석.** 카드 키워드는 상담사 화면에만 참고로 보인다. 해석은 상담사가 직접 쓴다.
- **다시 뽑기.** 상담사가 다시 섞으면 자리의 카드는 거두고, 이미 대화에 남은 카드 기록은 상담이 끝날 때까지 남는다.

## 기술 구조

화면은 GitHub Pages가 내려주는 정적 파일이고, 두 브라우저는 실시간 DB 하나를 통해서만 만난다. 직접 운영하는 서버는 없다.

구성 요소:

- 손님 브라우저(휴대폰): 가입 없이 입장하고, 초대 링크로 익명 로그인한다.
- GitHub Pages: 화면 파일을 내려준다.
- 상담사 브라우저(PC): 상담사 계정으로 로그인해 문을 열고 닫는다.
- 실시간 DB: 데이터 규칙이 권한을 지킨다. 문 상태는 누구나 읽고 상담사만 바꾼다. 상담실(대화와 펼쳐진 카드)은 그 상담의 두 사람만 읽고 쓴다. 덱 순서(섞인 순서와 방향)는 상담사만 읽고 쓴다.

**데이터 자리(1~4단계에서 확정)**

초대 링크의 끝에 붙는 코드가 곧 방 이름이다. 초대만 따로 담는 자리는 두지 않는다.

| 자리 | 담는 것 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| `door` | 열림 여부, 바뀐 시각 | 누구나 | 상담사 |
| `rooms/{방}/meta` | 만든 시각, 앉은 손님의 익명 ID, 상담을 시작한 시각 | 상담사. 빈 방은 링크를 가진 사람, 손님이 앉은 뒤에는 그 손님만 | 상담사. 손님은 문이 열려 있을 때 빈 방에 자기 ID를 한 번만. 시작 시각은 손님이 앉은 뒤에 상담사만, 서버 시각으로만 |
| `rooms/{방}/messages` | 메시지(보낸 쪽, 글, 시각). 상담사가 보낸 정해 둔 안내에는 안내 표시가 붙는다 | 그 상담의 두 사람 | 각자 자기 메시지만. 고치거나 지울 수 없고 1000자까지. 안내 표시는 상담사만 |
| `rooms/{방}/table` | 스프레드, 섞은 횟수, 손님이 고른 위치, 펼쳐진 카드 | 그 상담의 두 사람 | 고르기는 손님만(한 번 고르면 바꿀 수 없음). 펼치기는 상담사만, 덱의 그 위치에 있는 카드로만 |
| `rooms/{방}/presence` | 두 사람이 자리에 있는지(있음, 비움, 손님의 먼저 나감) | 그 상담의 두 사람 | 각자 자기 것만. 손님의 ‘먼저 나감’은 되돌릴 수 없다. 지워진 방에는 쓸 수 없다 |
| `rooms/{방}/typing` | 지금 글을 쓰는 중인지 | 그 상담의 두 사람 | 각자 자기 것만. 지워진 방에는 쓸 수 없다 |
| `private/current` | 지금 열려 있는 방 이름 | 상담사 | 상담사 |
| `private/{방}/deck` | 섞인 순서와 정·역방향 | 상담사 | 상담사. 손님이 고른 뒤에는 바꿀 수 없고, 다시 섞으면 고른 카드도 함께 비워진다 |

**로그인과 권한**

- 상담사는 계정 하나로 로그인하고, 데이터 규칙은 그 계정 하나만 상담사로 인정한다.
- 손님은 가입 없이 익명으로 로그인된다. 초대 링크로 자리에 앉는 순간 그 익명 ID가 그 방에 묶이고, 다른 기기는 같은 링크로 들어올 수 없다.
- 권한은 화면에서 단추를 숨기는 것으로 끝내지 않고 데이터 규칙에 적는다. 규칙은 저장소에 파일로 두고, 바꿀 때마다 “권한 없는 사람이 읽을 수 없다”를 시험한다.
- 메시지 길이와 보내는 속도에 상한을 둔다.

**실시간 DB 고르기**

| | Firebase Realtime Database (무료 Spark) | Supabase (무료) |
| --- | --- | --- |
| 상담소에 걸리는 제약 | 동시 연결 100개까지 ([한도 문서](https://firebase.google.com/docs/database/usage/limits)) | 일주일 동안 DB 활동이 너무 적으면 프로젝트가 일시정지된다. 데이터와 설정은 남는다 ([안내](https://supabase.com/kb/faqs/platform/free-project-pausing)) |
| 상담소에 주는 영향 | 1:1 상담은 한 번에 연결 두세 개라 한도에 닿지 않는다 | 며칠씩 문을 닫아 두면 정지될 수 있고, 그러면 문을 열기 전에 직접 되살려야 한다 |

실시간 DB는 Firebase Realtime Database로 정했다. 요금제 조건은 바뀔 수 있으니 0단계에서 두 문서를 다시 확인한다(위 내용은 2026년 11월 20일에 확인).

**바꾸지 않는 제약**

- GitHub Pages는 정적 파일만 내려준다. 서버 코드가 필요한 기능은 범위 밖이다.
- 무료 요금제 안에서 돌아가야 한다. 유료 기능이 필요해지면 사용자에게 먼저 묻는다.
- 상담이 끝난 뒤 `rooms`와 `private` 아래에 그 방의 데이터가 남아 있으면 버그다.

## 개인정보·안전·운영

손님에게서 받는 정보는 상담 중에 오가는 글뿐이고, 그것도 상담이 끝나면 지운다.

**남기지 않기**

- 이름, 연락처, 계정을 사이트에서 받지 않는다. 예약에 필요한 연락처는 사이트 밖의 예약 수단에만 남는다.
- 상담 마치기를 누르면 대화, 카드, 섞인 순서를 서버에서 삭제한다. 삭제한 뒤 상담사 화면이 서버를 다시 읽어 남은 것이 없는지 확인하고 알린다. 상담사가 마치기를 못 누르고 나간 경우에도 다음에 문을 열 때 남은 상담을 모두 지운다.
- 분석 도구, 광고 추적기, 대화 내용이 담기는 로그를 넣지 않는다.
- 손님이 자리에 앉기 전에 이용 약속을 한 화면으로 보여준다: 대화는 지워진다, 상대는 사람이다, 이곳은 치료나 의료가 아니다.

**상담의 범위**

- 상담소는 고민을 들어주는 대화와 타로를 제공한다. 심리치료, 진단, 의료·법률·투자 조언처럼 보이는 문구를 화면 어디에도 쓰지 않는다.
- 타로는 마음을 돌아보는 도구로 소개한다. 건강, 생사, 재판, 투자 결과를 단정하는 안내 문구를 만들지 않는다.

**이용 연령**

- 성인과 만 15세 이상 미성년자만 받는다. 만 15세 미만은 받지 않는다.
- 미성년 손님은 예약 단계에서 본인의 사전 동의를 글로 받은 뒤에만 초대 링크를 보낸다. 동의가 확인되지 않으면 링크를 보내지 않는다. 동의를 받을 때와 이용 약속 화면에서, 자살 위기나 가출 위기처럼 전문가의 도움이 필요한 이야기가 나오면 상담을 그 자리에서 멈춘다는 점을 미리 밝힌다.
- 이용 약속 화면에 나이 기준을 적고 해당 여부를 확인받는다. 생년월일 같은 나이 정보는 사이트에 저장하지 않는다. 확인했다는 사실도 저장하지 않는다.
- 받은 동의는 사이트 밖 예약 수단에 보관한다.

**위기 상황**

- 손님이 스스로를 해칠 생각을 비치면 상담사는 타로를 멈추고 전문 기관을 안내한다. 상담사 화면의 「안내 보내기」에서 위기 안내를 골라 한 번에 보낼 수 있게 한다(`/위기`, `/청소년` 명령으로도 보낸다).
- 안내에는 자살예방상담전화 109와 긴급 신고 119·112를 넣고, 미성년 손님에게는 청소년상담전화 1388도 함께 안내한다. 번호는 공개 전에 한 번 더 확인한다.
- 이 안내는 닫힌 문 화면과 이용 약속 화면에도 작게 둔다. 상담소가 닫힌 밤에 찾아온 사람이 갈 곳을 알 수 있어야 한다.

미성년 손님에게서 자살 위기, 가출 위기처럼 슈퍼바이저의 조언이 필요한 내용이 나오면 상담과 타로를 즉시 중단한다. 중단은 연결을 끊는 것이 아니다. present가 왜 멈추는지 말하고, 위기 안내(109, 1388, 119·112)를 보내고, 손님이 안내를 받은 것을 확인한 뒤에 상담을 마친다.

**예약과 결제**

- 예약은 사이트 밖에서 받고, 상담사가 예약된 손님에게 초대 링크를 보낸다.
- 돈을 받는다면 사업자 등록, 통신판매업 신고, 환불 기준, 개인정보 처리방침이 필요한지를 공개 전에 세무·법률 전문가나 관할 기관에 확인한다. Claude의 설명은 법률 자문이 아니다.

## 작업 방식

결정과 시안은 Claude 채팅에서, 구현은 Claude Code에서, 보관과 배포는 GitHub에서 한다.

| 도구 | 맡는 일 |
| --- | --- |
| Claude 프로젝트(채팅) | 방향 결정, 화면 시안, 문구, 카드 그림 방향, 이 문서 고치기 |
| Claude Code | 저장소 안에서 코드 작성, 데이터 규칙 작성과 시험, 배포 |
| GitHub | 코드 보관, Pages 배포, 이슈로 할 일 관리 |

**코드 규칙**

- 빌드 과정 없이 HTML, CSS, 자바스크립트 모듈만으로 만든다. 프레임워크를 쓰지 않는다.
- 색, 글씨, 간격은 CSS 변수 한 곳에서 정한다. 카드 목록과 화면 문구도 각각 파일 하나에 모은다.
- 서비스 계정 키, 비밀번호 같은 비밀 값은 저장소에 넣지 않는다. 접근 통제는 브라우저 코드가 아니라 데이터 규칙이 맡는다.
- `main` 브랜치가 공개된 사이트다. 작업은 브랜치에서 하고, 사용자가 확인한 뒤에 합친다.

```
/index.html          손님 화면 (문, 이용 약속, 상담실)
/counselor.html      상담사 화면 (로그인, 문 열기, 상담실)
/css/                색·글씨 변수, 화면별 스타일
/js/                 연결, 채팅, 타로, 상태 관리 모듈
/assets/cards/       카드 그림
/rules/              실시간 DB 데이터 규칙과 그 시험
/docs/               이 지침의 사본, 결정 기록
CLAUDE.md            Claude Code가 매번 읽는 요약 지침
```

**Claude가 일하는 순서**

1. 작업을 시작하기 전에 어느 단계의 무엇을 만들지 한 문단으로 말한다.
2. 범위 표의 「만들지 않는 것」이나 정해지지 않은 항목에 닿으면 멈추고 묻는다.
3. 끝나면 사용자가 직접 확인할 방법을 순서대로 알려준다(어느 화면에서 무엇을 누르면 무엇이 보여야 하는지).
4. 확인하지 못한 것은 확인하지 못했다고 말한다. 특히 두 기기 연결과 휴대폰 화면은 사용자의 확인이 있어야 완료다.

**완료의 정의**

- [ ] PC와 휴대폰 두 기기로 직접 해 보았다
- [ ] 폭 360px에서 가로 스크롤이 없고 입력창이 가려지지 않는다
- [ ] 브라우저 콘솔에 오류가 없다
- [ ] 연결을 끊었다 이어도 화면이 맞는 상태로 돌아온다
- [ ] 권한 없는 브라우저가 데이터를 읽거나 쓰지 못한다
- [ ] 새로 쓴 문구가 디자인 원칙의 문구 규칙을 따른다
- [ ] 이 문서와 달라진 점이 있으면 문서를 고쳤다

2026년 11월 21일에 카드 표기 두 가지를 더 정했다.

- **카드 이름.** The Fool은 ‘광대’, The High Priestess는 ‘여사제’로 적는다. 슈트는 완드·컵·소드·펜타클, 궁정 카드는 페이지·나이트·퀸·킹이다.
- **키워드.** 상담사 화면의 참고 키워드는 요즘 널리 쓰는 해석을 따른다. 리딩 자체는 present의 방식이 우선이고, 키워드는 참고일 뿐이다.
- 78장 목록과 키워드는 `js/cards.js`가 기준이다. 카드별 필수 상징은 Claude의 「78장 카드와 필수 상징」 표에 있다.

2026년 11월 21일, 3단계를 만들며 상담 길이를 코드 한 곳(`js/session.js`의 `SESSION_MINUTES`)에 두었다. 모의 상담 뒤에 길이를 바꾸면 이 값과 이용 약속 문구가 함께 바뀐다.

2026년 11월 21일에 두 가지를 더 정했다.

- **이어서 상담받는 손님.** 사이트에는 누구의 기록도 남기지 않는다(사이트는 나이를 저장하지 않아 성인과 미성년자를 구분할 수 없다). 다음 약속은 예약 수단에서 잡고 매번 새 초대 링크를 보낸다. 지난 상담의 메모는 성인 손님이 동의한 경우에만 상담사가 사이트 밖에 남기고, 미성년 손님은 남기지 않는다.
- **정해 둔 안내.** 상담사는 미리 써 둔 안내문(위기 안내, 시간 안내 등)을 단추나 `/이름` 명령으로 보낼 수 있다. 안내문은 사람이 미리 쓴 글이고 AI가 쓰지 않는다. 대화에서는 present의 말과 구분되는 「상담소 안내」로 보인다. 보통 문장 속의 단어를 감지해 자동으로 보내지는 않는다(뜻하지 않게 나가는 일을 막기 위해서다). 안내문은 `js/copy.js`의 `notices`에 모은다.

같은 날 두 가지를 더 정했다.

- **미성년자 여부 확인.** 사이트가 아니라 예약 단계에서 태어난 해(연도만)와 「만 15세 이상」 확인을 받는다. 신분증 사본이나 주민등록번호는 받지 않는다. 상담을 시작할 때 한 번 더 묻고, 확실하지 않으면 미성년자로 보고 미성년자 규칙을 적용한다.
- **상담실의 시작 안내.** 상담실에 들어오면 대화창 맨 위에 채팅 규칙과 미성년자 안내가 「상담소 안내」로 보인다. 서버에 저장하지 않고 두 화면이 각자 그린다. 문구는 `js/copy.js`의 `chat.intro`에 있다.

- **카드 그림의 방향.** 양피지 바탕에 먹선과 금색 포인트로 그린 자체 선 그림으로 간다. 1909년 원본의 도상만 참고하고, 유니버셜 웨이트를 비롯한 뒤의 판본의 채색과 뒷면 무늬는 따르지 않는다(처음 정한 「웨이트 계열 도상을 따라 새로 그린다」와 같은 방향이다). 「라이더 웨이트」, 「유니버셜 웨이트」라는 이름은 화면과 홍보에 쓰지 않는다. 원하면 나중에 이 선 그림을 밑그림으로 삼아 AI 이미지 도구로 질감을 입혀 볼 수 있고, 그때도 입력은 이 선 그림과 1909년 원본까지만 쓴다.
- **카드 크게 보기.** 펼친 카드를 누르면 누른 사람의 화면에서만 크게 보인다. 상대 화면에는 영향을 주지 않는다.
- **그림 파일.** `assets/cards/번호.svg`(00~77)에 그림만 담고, 번호와 이름은 화면이 글자로 얹는다. 그림이 있는 카드의 수는 `js/cards.js`의 `ART_CARDS`가 정한다. 그림은 카드가 펼쳐진 뒤에만 불러온다.

2026년 11월 21일, 공개를 준비하며 홍보·예약·운영을 이렇게 정했다.

- **대상.** 처음에는 청소년과 성인 모두에게 알린다. 한 달쯤 해 보고(미성년 예약의 비율, 위기 안내를 보낸 횟수) 맞지 않으면 성인 위주로 바꾼다.
- **여는 때.** 일주일에 세 번, 밤 10시와 11시에 한 사람씩(하루 최대 2명)으로 시작한다. 시험 기간에는 하루 1~2명만 받는다. 늘릴지는 한 달 뒤에 정한다.
- **예약.** 사이트 밖에서 받는다. 카카오톡 채널의 1:1 채팅으로 문의를 받고 초대 링크를 보낸다. 태어난 해, 「만 15세 이상」 확인, 미성년자 사전 동의, 이용 약속 동의는 예약 폼으로 받는다. 예약 장부(별명, 날짜, 상태, 성인·미성년, 메모 동의 여부)는 사이트 밖의 표에 두고 정한 기간 뒤에 지운다.
- **링크 미리보기.** 사이트 주소를 메신저나 SNS에 붙이면 그림과 이름, 한 줄 소개가 카드로 보이게 한다(`index.html`의 og 태그, 그림은 `assets/og.jpg`). 그림은 열린 문 안쪽으로 보이는 방(촛불 하나, 뒷면이 보이는 카드 세 장, 빈 의자)이고 왼쪽에 이름을 얹는다. 그림을 바꾸면 og 태그의 그림 주소 뒤 `?v=` 숫자를 올려 메신저가 새 그림을 받게 한다. 상담사 화면에는 넣지 않는다.
- **문 그림.** 문 화면의 문은 선으로 그린 도형 대신 그림 두 장(불 꺼진 문 `assets/door-off.jpg`, 불 켜진 문 `assets/door-on.jpg`)을 쓴다. 문이 닫혀 있으면 불 꺼진 그림이 보이고, 열리면 불 켜진 그림이 천천히 떠오른다(움직임을 줄인 설정에서는 바로 바뀐다). 그림은 우리가 그린 문을 밑그림으로 사용자가 AI 이미지 도구에서 만든 것이고, 두 장은 같은 자리에서 같은 크기로 잘라 겹쳐도 어긋나지 않게 한다. 손님 화면과 상담사 화면이 같은 그림을 쓴다. 채널 사진과 홍보에는 문이 아니라 문 안쪽의 아늑한 방을 그린 그림을 쓴다(사람과 글자는 넣지 않고, 카드는 뒷면만 보이게 한다).
- **예약 채널.** 카카오톡 채널 「present의 밤」(https://pf.kakao.com/_PhGvX). 「상담소」가 들어간 이름은 카카오의 금칙어에 걸려 쓰지 못했다. 안내 화면에는 채널 이름을 함께 적어 손님이 헷갈리지 않게 한다.
- **안내 화면의 말투.** 합니다체로 쓰고, 여는 때·진행 순서·미리 알아 둘 것과 present 소개는 명사로 끝낸다. 초대 링크 없이 온 사람에게는 문 상태 글도 합니다체로 보인다.
- **안내 화면.** 초대 링크 없이 온 사람이 보는 문 화면 아래에 안내를 붙인다(주소는 하나). 내용: 어떤 곳인지, 듣는 사람, 여는 때, 진행 순서, 미리 알아 둘 것, 예약. 방문자 분석 도구, 꾸며 쓴 후기, 「치료」·「진단」·「적중」 같은 표현은 넣지 않는다. 문구는 `js/copy.js`의 `landing`에 있다.
- **present 소개.** 충북대학교 심리학과 졸업, 1년 동안 타로로 사람들의 이야기를 들었다는 것만 적는다. 자격은 뭉뚱그려 적지 않는다. 적게 되면 정확한 이름(직업상담사 2급)으로 적는다.
- **홍보.** 모든 홍보는 안내 화면의 주소 하나로 보낸다. 인스타그램 계정과 블로그 글, 동의받은 소감으로 조용히 알린다. 오픈채팅방 운영과 광고 집행은 하지 않는다(광고는 유료 여부가 정해진 뒤에 다시 본다).
- **사이트 주소.** `https://presentnight.com`을 쓴다(채널 이름 「present의 밤」과 같은 뜻). 가비아에서 사용자 이름으로 샀고 해마다 갱신한다(첫 만료 2027년 11월 21일). 화면 파일은 그대로 GitHub Pages가 내려주고, 주소만 가비아의 DNS로 연결한다. 예전 주소(`hyunjae0110.github.io/night-counsel`)로 온 사람은 새 주소로 넘어간다. 초대 링크는 상담사 화면이 열려 있는 주소로 만들어지므로 따로 고칠 곳이 없다. 주소가 적혀 있는 곳은 `index.html`의 링크 미리보기 태그와 카카오톡 채널의 홈페이지 칸이다. 가비아 계정의 비밀번호와 결제 정보는 저장소와 문서에 적지 않는다.

**남은 것**

- **판 번호.** 화면 파일 주소에 `?v=숫자`를 붙여, 합친 뒤 새로고침하면 바로 새 파일을 받게 한다. 화면 파일을 바꿀 때마다 두 HTML의 숫자를 함께 올린다. 카드 그림은 `ART_VERSION`으로 따로 올린다.
- **소리.** 손님이 자리에 앉는 순간 상담사 화면에서만 작은 종소리가 한 번 난다(소리 파일 없이 브라우저가 만든다). 새로고침으로 이미 앉아 있는 방을 다시 볼 때는 울리지 않는다. 손님 화면에는 소리가 없고, 켜는 단추도 아직 두지 않았다.
- 공개하는 날 `index.html`의 검색 차단 표시(`noindex`)를 뺀다. 지금은 검색에 나오지 않게 막아 두었다. 상담사 화면은 계속 막아 둔다.
- 예약 폼을 만든다. 안내 화면의 예약 단추는 주소를 넣어 두었고 닫아 둔 상태다. 사용자가 열자고 하면 `js/copy.js`의 `landing.reserve.open`을 참으로 바꾼다.
- 늦게 온 손님을 10분 기다리고 닫는 규칙과 「변경은 전날까지」 규칙은 Claude가 제안한 초안이다. 사용자의 확인을 기다린다.
- 78장의 그림을 모두 그렸다. 사용자가 가진 카드와 대조해 고칠 곳을 찾는 일이 남았다.
